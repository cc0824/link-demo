# 页面工作台实现计划

2026-11-17。用户要求将当前Demo功能全部通过页面操作，沿用Java17、Spring Boot和现有商品展示风格，不引入独立前端工程。

## 范围

- 首页可发现“演示工作台”，同时直接提供商品1001/1002入口。
- 工作台分商品、分享链接、访问统计三个区域，移动端可用。
- 商品区域可选商品、查看详情、修改标题、上下架、删除和单独恢复演示商品。
- 分享区域选择商品/分享人/渠道，创建并复制链接、打开卡片或访问商品，最近100条记录从数据库加载。
- 统计区域按日期、渠道、分享人、短链和分组查询真实PV/UV；日期UI结束日包含，提交接口时转为次日排他边界。
- 异常演示可点击失效链接；1002展示缺省元数据；下架/删除后从已有分享链接查看降级。
- 仅demo profile注册新工作台及API；所有数据API继续校验Bearer Token，页面不嵌入服务端实际密钥。默认演示Token自动尝试，自定义Token在页面输入，仅保存在当前页面内存。
- 提供明确加载、操作结果和错误提示；删除、重置有确认，重置文案说明会清空短链和统计。单独恢复商品保留归因和访问记录。

## 接口与文件

- 新增 `GET /api/demo/products`：固定演示商品清单，保留DELETED占位以便恢复。
- 新增 `POST /api/demo/products/{id}/restore`：只恢复1001/1002缺失行，现存商品不覆盖；重复调用幂等。
- 新增 `GET /api/demo/links`：按创建时间倒序返回最近100条，包含商品状态、分享人与渠道、可用URL。
- 新增 `GET /workbench`、`templates/workbench.html`、`static/workbench.css`、`static/workbench.js`。
- 修改商品/短链仓库、Demo控制器、首页模板与页面导航；CSP允许同源外部脚本和同源fetch，不允许内联脚本。
- 新增 `WorkbenchTest` 覆盖API鉴权、profile范围、商品恢复与统计保留、历史列表和页面不泄露密钥。

## 执行顺序

1. API行为测试先失败，然后实现最小后端扩展。
2. 服务端输出页面骨架，外部JS负责表单与反馈，通过已有API完成操作。
3. 全量Java测试和格式检查；真实浏览器验证选择1002、生成/复制/访问、统计、上下架、删除/恢复。
4. 更新README、决策与验证记录，保留已有数据，使用独立测试数据库进行页面验收。

验收以实际操作和数据变化为准，不以按钮存在或静态页面截图替代业务验证。
